# Ressources communes — Semaines 1 et 2

Cette page rassemble les liens cités dans les six notes du bloc. Les ressources restent également indiquées à la fin de chaque note, près des notions auxquelles elles se rapportent.

## Références générales sur les tests

- [ISTQB — Certified Tester Foundation Level (CTFL) v4.0](https://istqb.org/certifications/certified-tester-foundation-level) : page officielle du programme, avec accès au syllabus et aux examens blancs.
- [ISTQB — Syllabus CTFL v4.0.1 (PDF)](https://istqb.org/?sdm_process_download=1&download_id=3345) : syllabus de référence couvrant les fondamentaux, le cycle de vie, les techniques statiques, la conception, la gestion et les outils.
- [Glossaire ISTQB](https://glossary.istqb.org/) : définitions normalisées, notamment pour les niveaux, types et techniques de test, la couverture, les revues et la gestion des défauts.
- [CFTL — Comprendre les tests](https://cftl.fr/tests-logiciels/comprendre-les-tests/) : ressources en français du Comité Français des Tests Logiciels.

## Cycle de vie et approches Agile

- [Manifeste Agile — version française](https://agilemanifesto.org/iso/fr/manifesto.html) : valeurs et principes qui fondent le développement Agile.
- [GitHub Docs — Intégration continue avec GitHub Actions](https://docs.github.com/en/actions/automating-builds-and-tests/about-continuous-integration) : exemple de CI qui construit un projet et exécute des vérifications lors des changements.
- [Cucumber — Behaviour-Driven Development](https://cucumber.io/docs/bdd/) : collaboration autour d’exemples concrets de comportement et leur formulation.
- [Cucumber — Référence Gherkin](https://cucumber.io/docs/gherkin/reference/) : syntaxe des scénarios, notamment `Given`, `When`, `Then` et les tableaux d’exemples. Gherkin est une notation, pas à lui seul une méthode complète d’ATDD.

## Techniques statiques et analyse de code

- [ESLint — À propos](https://eslint.org/docs/latest/about/) : linter JavaScript réalisant une analyse statique du code et signalant certains motifs problématiques sans exécuter le programme.

## Gestion des tests et des défauts

- [Microsoft Learn — Azure Test Plans](https://learn.microsoft.com/en-us/azure/devops/test/overview?view=azure-devops) : plans, suites, cas, exécutions manuelles, résultats et traçabilité.
- [SmartBear — Présentation des plans de test Zephyr](https://support.smartbear.com/zephyr/docs/en/test-plans/test-plans--overview-.html) : organisation des cas, cycles d’exécution, plans et rapports.
- [TestRail — Gestion des tests](https://www.testrail.com/test-management/) : exemple de gestionnaire spécialisé pour planifier et suivre tests, exécutions et résultats.
- [GitHub Docs — Démarrage avec GitHub Issues](https://docs.github.com/en/issues/tracking-your-work-with-issues/quickstart) : suivi collaboratif des tâches et défauts, avec étapes de reproduction, résultats attendus et observés, étiquettes et affectation. Un outil de tickets ne remplace pas nécessairement un gestionnaire de cas et de campagnes de test.
